You are building the full MVP backend + frontend for RecycleLah, a recycling pickup platform with three interfaces: SELLER, COLLECTOR, and ADMIN. The system must be mobile-first, secure, and structured cleanly for future conversion into a mobile app.

===========================================================
AUTHENTICATION SYSTEM (EMAIL + PASSWORD + GOOGLE LOGIN)
===========================================================
1. Standard login:
   - Username/email + password
   - Role selection: SELLER or COLLECTOR
   - Phone number required

2. Google OAuth login:
   - Use Google Identity Services
   - Capture: email, name, Google ID
   - If new user → onboarding flow (choose role, phone, IC verification)
   - If existing user → login immediately

3. Duplicate prevention:
   Before creating ANY account:
   - Check if IC number exists (encrypted)
   - Check if email exists
   - Check if phone number exists
   If any match → block registration with message:
   “Account already exists. Please log in instead.”

===========================================================
ADMIN DETECTION (EMAIL-BASED)
===========================================================
1. Add environment variable: ADMIN_EMAILS
   Example: “admin@recyclelah.com, hafiz@hazkilgroup.com”

2. If login email matches ADMIN_EMAILS:
   - Assign role = ADMIN
   - Skip IC verification
   - Redirect to admin dashboard

3. Admin routes must be protected by middleware.

===========================================================
IC VERIFICATION MODULE (FRONT + BACK + OCR)
===========================================================
1. Capture IC front photo:
   - Mobile-friendly camera capture
   - Preview before upload
   - Compress image
   - Upload to secure storage (Supabase or Firebase Storage)
   - Return secure URL

2. Capture IC back photo:
   - Same flow as front

3. OCR extraction:
   - Use Tesseract.js or external OCR API
   - Extract:
     - Full name
     - IC number
     - Address (optional)
   - Validate IC format (Malaysia NRIC: YYMMDD-XX-XXXX)

4. Verification logic:
   - Compare extracted IC number with user input
   - Mark user as “Verified” if match
   - Store:
     - IC number (encrypted)
     - Front IC URL
     - Back IC URL
     - Verification status

5. Security:
   - Do NOT store raw images in Replit DB
   - Encrypt IC number
   - Use environment variables for storage keys

===========================================================
ESCROW + WALLET LOGIC
===========================================================
1. Seller must have enough balance to create job.
2. When collector accepts job:
   - Lock seller’s amount into ESCROW (internal ledger)
3. After receipt verification:
   - Release ESCROW:
     - Collector payout
     - Platform commission
     - Seller receives remaining amount (if applicable)
4. Wallet top-up:
   - Use mock FPX API (ToyyibPay/Billplz placeholder)
5. Withdrawal:
   - Manual approval by admin
